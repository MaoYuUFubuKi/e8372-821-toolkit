# 操作指南

按以下步骤手动操作，也可交给 [Agent](../AGENTS.md) 执行。

## 完整操作流程

### 1. 检查环境，备份设备

在项目目录打开终端。请先确认主板与固件版本，保持自己的有效 SIM 在卡槽中。

```sh
python3 scripts/setup_runtime.py
./run.sh doctor
./run.sh backup my-device
```

看到“程序已就绪”后，拔下设备，等 3 秒，插回同一个接口。备份过程需要按提示拔插两次，不按 Reset。裸板上电前移开拆下的金属罩和工具。运行结果保存在私人目录 `local/my-device/`。

### 2. 准备修改版和恢复包

下列版本参数应来自你自己的设备，不能只照抄：

```sh
./run.sh prepare my-device \
  --board 8BC010-U15L_V1.03 \
  --soc ASR1803S \
  --firmware U15L-MT02B01V15-L01
./run.sh check my-device
```

当前仅发布源码，从自己的备份生成修改版；可加 `--method local` 明确选择本机生成。原版指纹不匹配就停止。

将生成的 `local/my-device/prepared/recovery.zip` 另存一份。里面是**自己的原版数据与独立恢复工具**，不要上传。

### 3. 刷入并验证

```sh
./run.sh install my-device --write
```

按窗口提示完成五次拔插：保存现状 → 写回原版 → 读回验证 → 写入修改版 → 再读回验证。提示正在写入时保持连接。原版恢复失败不会继续刷修改版；发生异常时按程序提示进入恢复。

结束后再拔插一次正常启动，可用 `./run.sh status` 读状态。最后用手机连接设备 Wi-Fi，关闭手机蜂窝数据，打开未缓存网页确认上网。

### 4. 需要恢复原版时

```sh
./run.sh restore my-device --write
```

或解压自己保留的 `recovery.zip`，双击其中的 `恢复原版.command`。按提示完成保存现状、恢复、核验三次拔插。恢复原版会恢复卡商校验。

管理页连接、错误处理、固定组件和 Reset 的说明见本指南。正常重启已验证；恢复出厂预计保留程序修改，但还未实测 Reset。



## 管理页面连接

本次设备管理地址是 `192.168.0.1`。USB 网卡自动获取地址后可能被选为默认出口；直接停用整张网卡又会失去管理页连接。

1. 打开 macOS 系统设置 → 网络，确认哪个服务属于这个 USB 随身 Wi-Fi。可以拔插前后比较服务列表；不要选正在上网的 Wi-Fi 或有线网络。
2. 记录该 USB 服务原来的 IPv4、IPv6、代理和启用状态，便于恢复。
3. 为它配置手动 IPv4 `192.168.0.2`，子网掩码 `255.255.255.0`。路由器/默认网关留空；命令行对应 `0.0.0.0`。
4. IPv6 可设为“仅本地链接”，避免设备成为新的 IPv6 默认出口。保持服务开启。不要把已有主网络也禁用。
5. 打开 `http://192.168.0.1/`。若电脑主网络也使用 `192.168.0.0/24`，先处理网段冲突，不能盲目套用这组地址。

有明确服务名时，Agent 可以先检查并展示将作用于哪个服务，再按已有授权操作：

```sh
networksetup -listallhardwareports
networksetup -listallnetworkservices
networksetup -getinfo '你已确认的USB服务名'
```

需管理员权限的命令由用户在本机终端输入系统密码：

```sh
sudo networksetup -setmanual '你已确认的USB服务名' 192.168.0.2 255.255.255.0 0.0.0.0
sudo networksetup -setv6linklocal '你已确认的USB服务名'
sudo networksetup -setnetworkserviceenabled '你已确认的USB服务名' on
curl --noproxy '*' --connect-timeout 5 --max-time 10 http://192.168.0.1/
```

这里只建立管理连接，电脑不会因此自动用随身 Wi-Fi 上网。最终联网测试使用手机连接该 Wi-Fi，并关闭手机蜂窝数据。恢复电脑设置时按第 2 步的真实记录恢复；不要假设所有人的原配置都是 DHCP、自动 IPv6 和停用。

## 常见问题

| 现象 | 核对和处理 |
| --- | --- |
| 插入后电脑断网 | USB 网卡可能成为默认出口；按管理网络说明保留本地连接，不把整张网卡禁用。 |
| 程序刚启动就结束 | 可能捕获了旧启动会话；按“已就绪”后重新上电。不要按复位键。 |
| 打开接口时 ENODEV | 启动接口正在切换；仅在还没发出协议命令前重新捕获。 |
| 能查版本，读数据一直超时 | 读取前的 GetVersion 可能切换了协议状态；对照读取命令顺序，不盲目加超时。 |
| `0x64` | 本次对应闪存类型不支持；正确子类型为 27。不要连续枚举任意参数。 |
| RAM 读取 `0x05` | 当前请求不受支持，不等于已经证明读保护。原版项目不需要这一失败路线。 |
| 高低地址大部分一样、配置区域不同 | 不同上电间配置可能变化；需要同一次上电读两遍，再比较高低范围。 |
| 只有 4 KiB / 64 KiB 文件 | 分别可能只是样本/配置导出，不是主闪存备份。 |
| 变更页面 `sim_not_match` 仍无网络 | 配置值与内部断网状态不一定是一回事；必须追踪真实调用链。 |
| 原生 Unicorn 启动崩溃 | 本次使用 Rosetta + x86_64 wheel 的研究环境；见环境文档。 |
| Agent 环境不能打开 USB | 先区分环境权限与设备问题；必要时由用户运行已经准备好的终端程序。 |
| 固件指纹不匹配 | 停止。不要编辑哈希常量或根据“都是 U15L”强行套用。 |
| 写入后只看到 Ready | 还要新上电、两遍完整读回，之后验证正常启动和真实网页访问。 |
| 修改版写入中断 | 合并程序会尝试转入原版恢复；也可用本机自己的独立恢复包。保留记录，不刷整片或别人的固件。 |
| 恢复入口也不出现 | 软件恢复条件不满足，停止继续试写；本项目不保证所有硬件故障都能救回。 |

遇到新错误，报告命令阶段、错误码、程序版本和去除身份数据后的摘要即可。不要公开完整备份、配置、SIM 卡号、认证头或管理密码。

## Reset 与分享固件

### 按 Reset 后还能用自己的卡吗

**正常恢复出厂设置预计保留本次修改，但当前没有实测这块板子的 Reset 按钮恢复出厂。**

本次改动在 CODE_PL 程序段；管理页面的恢复出厂操作调用 `restore_defaults`，与固件升级入口不同。按配置复位理解，它不会把程序段自动变回原厂版本。这是基于已知修改位置和管理接口的推断，尚未完整追踪实体按键所有分支，不能写成实测结论。

Wi-Fi 名、密码、管理密码、APN 等配置可能恢复默认，重置后需要重新连接及检查拨号设置。具体长按时长没有确认，本项目不编造按键步骤。

正常拔插重启已经验证；它与恢复出厂不同。恢复原版工具会把原卡商校验写回来；后续固件更新如果覆盖修改程序段，也会覆盖本次修改。项目没有修改自动更新设置，也未验证未来升级的行为。

### 为什么不直接分享作者的 16 MiB 备份

本次对原机整片备份的检查实际检出了：

- IMEI、序列号、MAC、SSID；
- Wi-Fi 密码、管理密码；
- SIM 的 ICCID、IMSI。

公开该文件会直接披露这些信息。别人整片刷入还可能复制设备身份和配置，造成重复标识；校准数据也不应拿去替换别人的设备。SIM 标识被检出不等于获得 SIM 的认证密钥，本次备份不能据此被描述为“复制了一张 SIM”。

固定组件只含已修改的程序段，不把作者的配置区带过去。其压缩及解压内容未检出上述已知值；已检查 ASCII/UTF-8、UTF-16、数字 BCD/半字节互换和原始 MAC 编码。已知值检查无法排除所有未知编码或潜在秘密。

### 别人使用时怎样保留自己的数据

固定组件和本机生成都要求对方先备份、核对原版指纹，再生成自己的恢复包。实际写入窗口的边缘字节来自对方自己的备份。原版不同不会因为型号相似就继续；这也不是一个“任何 U15L 都能刷”的包。

当前只发布源码，使用者从自己的原版生成。原厂固件组件的再分发许可目前没有确认，MIT 只覆盖项目原创代码，不能替原厂授权。

源码中的照片按作者要求暂时保留原画面。照片标签也会暴露密码和标识，公开前仍由作者处理，见 [发布说明](publishing.md)。

## 固定程序组件

前次实验提取过 `code-pl-u15l-mt02b01v15-l01-patched.lzma`，当前源码不附带该文件，共 1,268,216 字节（约 1.21 MiB）。它取自本次成功刷入后两遍一致的真机读回数据，仅包含修改后的 CODE_PL 压缩程序。

SHA-256：`423e5f4ad63f4b9fe39a6c3929b07679944e4d57d179c4c2f87af2ecc509480b`

这不是整片刷机镜像，也不是管理页面升级文件。不要自行把它写到 0 地址或上传到网页升级入口。现有工具会核对原机指纹，填入 `0x481000..0x5b7000` 的程序槽位，再用本机数据补齐实际写入窗口的两端。

### 默认怎么选

`prepare` 默认 `--method auto`：

1. 核对自己的两份备份、板号、原固件、TIM、OBM、解压后原代码。
2. 附有固定组件时，核对组件清单和固定哈希，再逐字节验证其解压内容等于自己的原代码加指定 4 字节改动。
3. 没有附组件的源码版，从使用者原版生成相同修改。
4. 两条路线都生成本机恢复包，再走同一套原版恢复验证、修改版写入、完整读回流程。

可明确选择 `--method fixed` 或 `--method local`。固定组件损坏或只剩半套文件时，默认模式报错，不偷偷改用另一种方式。原版不匹配时两条路线都会拒绝。
